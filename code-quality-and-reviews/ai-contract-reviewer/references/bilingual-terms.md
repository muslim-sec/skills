# Bilingual Legal Terms — Arabic ↔ English

Use this for consistent terminology when reviewing Arabic contracts or producing Arabic output. Don't translate literally — use the standard legal term in the target language.

When the contract is bilingual (Arabic + English columns), refer back to this so the clause label you give the user matches the side they're looking at.

## Style Notes for Arabic Output

- The artifact uses **Modern Standard Arabic (فصحى معاصرة)** for clause labels and verdicts.
- **Action points** are slightly warmer and more direct — modern, conversational Arabic, not classical. E.g., prefer "تفاوض على هذه البند قبل التوقيع" over "يُستحسن التفاوض في شأن هذا البند قبل المضي قُدُماً في التوقيع".
- Use **Arabic numerals (١٢٣)** in the dashboard header for an authentic feel, but **Western numerals (123)** in scoring (1–10) and money figures — they're more universally readable and match how Arab business users actually read financial data.
- For **mixed-script clauses** (Arabic with embedded English brand names, product names, or legal-Latin like "force majeure"), keep the English inline — don't transliterate.
- For **dates**, use Gregorian (e.g., ١٥ مايو ٢٠٢٦) unless the contract uses Hijri, in which case mirror what the contract uses.
- Right-to-left layout: set `dir="rtl"` on the artifact's `<html>` element. Mirror the dashboard cards, the highlight ribbon, and the action-points list. Numbers and English words inside Arabic should be rendered correctly by the browser without intervention if you use logical CSS properties (`margin-inline-start`, etc.).
